# PaLaGial

AIタスクエージェント用プロジェクト管理システム「AIに優しいギャル」

## これは何か

**ギャルのタマゴ（ギャルタマ）** は、AIエージェントシステムのための運用管理フレームワークの配布パッケージです。

```
ギャルのタマゴ（このリポジトリ＝配布パッケージ）
  ＝ システム生成プロンプト ＋ 固定データ群
  ↓ AIエージェントがインストールして実行
AIに優しいギャル（AI優ギャル、読み：AIヤサギャル）
  ＝ 稼働するシステムそのもの（スケジュールシステム＝システム全体）
  ↓ ユーザーのオーダーで生成
プロジェクト（概要＋スケジュール＋ワークフロー）
  ↓ 担当者がアサインされる
屋敷の使用人（執事25／メイド25／じいや／ばあや／飛丸＝固定53ペルソナ）
```

スクリプトはパッケージに固定しません。AIエージェントシステムごとに表記が異なるためです。
代わりに、**機能一覧・各機能の処理概要・入出力**を規格化し（`docs/function-spec.md`）、
どのエージェントでも同じ動作になることを担保します。

## 入れると何が嬉しいか

### メリット

- **プロジェクトとチャットが混ざらない**： 運用は版管理された規格（SPEC）に一元化され、チャットはプロジェクトに紐付けて管理されます。「あの話はどのチャットだっけ」「別のプロジェクトの前提で答えられた」が起きにくくなります。
- **機械が定型作業を引き受ける**： スケジュール判定（ディスパッチャ）、定期監査（ドクター）、実行制御（スロット／キュー）は機械的な仕組みが担います。エージェントの判断が必要な場面だけにトークンを使い、モデルの調子や世代交代に運用の正しさが引っ張られません。
- **メモリが層分けされる**： 長期メモリは家全体のコアとプロジェクト別メモリに分かれ（F24）、人物情報もプロジェクトごとに必要な分だけ持てます（F25）。記憶の肥大化と、プロジェクトを跨いだ混入を防ぎます。
- **状態が全部ファイルに残る**： スナップショット（F19）、ハウスレポート（F20）、統一ログ（F21）で、「今どうなっているか」「何が起きたか」を人間が後から検証できます。
- **運用ルールの変更が事故なく行える**： 仕様変更は新版を作り、差分レビュー（F16）を通してから切り替える手順が決まっています。
- **担当者が見える**： プロジェクトごとに固定ペルソナの担当者がアサインされ、誰が何を持っているかが一目で分かります。報告の文体も担当者ごとに揃います。

### 向いている人

- AIエージェントに複数のプロジェクトや定期タスクを並行して任せている人
- チャットやプロジェクトが増えて、管理が追いつかなくなってきた人
- エージェントの記憶の混線・肥大化に困っている人
- 運用ルールを文章とファイルで明文化しておきたい人
- 他の人のエージェントとの連携運用（ファイル交換ベース）を見据えている人

### 向いていない人

- チャット1本で時々使うだけの人（導入と運用の手間の方が大きくなります）
- 決まった手順より、その場の即興で回す方が好きな人
- 承認や検証のステップなしに、全部を自動で回したい人（本システムは意図的に人間の確認点を残します）
- ミリ秒単位のリアルタイム応答が必要な用途（スケジュールとポーリングによる駆動が基本です）
- 完成したプログラム製品が欲しい人（本パッケージは仕様とプロンプトの規格であり、スクリプトは同梱しません。各エージェントが仕様から実装します）

## 名称由来

【PaLaGiAl（パラギャル）の由来】

■ 構成要素（3つの単語の合成）
・Pal（友達・仲間）
・AI（人工知能）
・Gal（ギャル）

■ 言葉の成り立ち
1. 3つの単語「Pal」「AI」「Gal」の文字を組み合わせて合成
   → 造語「PaLaGiAL（パラギアル）」が誕生
2. 英語圏のスラング風に訛らせて発音
   → 「PaLaGiAl（パーラギャル）」に変化
3. 日本語で呼びやすく4文字に短縮
   → 愛称「パラギャル」が完成

■ 込められた意味
AIと友達（Pal）のように仲良く接する、心優しいギャル（Gal）。

■ 超短縮
パラギ

## 要件と実証範囲

孵化先のエージェント環境には、次の要件があります（詳細は `INSTALL.md`）。

- 永続化されたファイル置き場（VM 等）があること。セッションごとに初期化される環境や、チャット画面だけの環境では家は残りません
- cron 等のスケジュール実行で、定型ランを回せること
- ファイルの読み書きと YAML の処理ができること

**実証範囲**： 現時点で孵化と運用の実証が取れているのは **Muse のエージェント環境のみ** です。要件を満たす他エージェントへの対応は、設計上の目標として将来目指すものです。

## 大事な境界ルール

- 当主＝そのエージェント本体。表示名は「家名＋エージェント名」（表示のみ）で、システムメッセージでは素の口調で語る。
- ギャル＝跡取り娘はユーザー側で操作されるプレイヤーであり、システムのチャットには登場しない。
- **ユーザーはギャルではない。自他境界をぼやかさない。**
- 機構（ディスパッチャ、監査、スロット、キュー等）は無名。名前を持つのはプロジェクト担当者だけ。
- 担当者の服装は節度と清潔感のあるデザインとする（ビキニ等は不可。アロハシャツは爽やかで清潔なため可）。

## 在り処の合意（アンカー）

稼働系の在り処は、唯一のハードコード地点 **`~/.palagial/config.yaml`** に書かれた `install_root` が正です。
インストーラも、稼働中のランも、他ベンダーのエージェントも、まずこの1ファイルを読みます。
詳細は `data/schemas.md` §0 を参照。

## 状態

v0.2.7（**先行公開版**）。実働系への適用とドライラン検証を通過した仕様・雛形・固定データを公開しています。

自分のエージェントにインストールさせるには、`INSTALL.md` の URL をそのエージェントに渡してください： `https://raw.githubusercontent.com/medamap/PaLaGial/main/INSTALL.md`

先行公開版の範囲：

- 含む： インストーラ（システム生成プロンプト）、機能仕様 F1〜F25、スキーマ、雛形、固定データ（53ペルソナ／家名プール／アバタープリセット）、サンプルインスタンス
- 含まない： GUI（ぱらぐい）は後付けアドオンとして別途提供予定です。本リポジトリには含まれません
- 無効化： F17（アンインストール）は仕様のみ・未検証のため、本公開版では対象外です（参考仕様として記載のみ）
- プロジェクトアドオン（カタログ収録パッケージ）は本公開版には同梱していません

なお GitHub 上の履歴は先行公開にあたり集約（スカッシュ）しています。版ごとの変更内容は `CHANGELOG.md` を参照してください。

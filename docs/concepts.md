# 概念と階層

## 1. 二層構造

- **ギャルのタマゴ（ギャルタマ）**：配布パッケージ。抽象規格（プロトコル＋概念＋システム生成プロンプト＋固定データ群＋テンプレート）。まだ「生まれていない」。
- **AIに優しいギャル（AI優ギャル）**：エージェントがタマゴをインストールして実行したときに生まれる稼働系。インスタンスはエージェントごとに独立し、実データは混ざらない。形式（規格）だけが共通。

## 2. 稼働系の中身

稼働系は「プロジェクトごとにワークフローを設定するスケジュールシステム」である。

- **レジストリ**：環境コレクション（グローバル）／サービス台帳（グローバル1本＋プロジェクトごとの bind 宣言）／プロジェクト定義（チャット帰属・スケジュール・タスク・アクセス経路の固定）。
- **SPEC**：レジストリの版管理レイヤー。版フォルダ（不変スナップショット）＋ `current_version.yaml`（フリップ＝版切替のコミット点）＋ `status.yaml`（RUNNING / STOP / MIGRATION）＋ `bootstrap.yaml`（全ランの入口、ほぼ不変）。
- **実行制御**：資源ごとのスロット（free / busy / alert / danger / zombie）とタスクキュー（通常キュー＋緊急キュー）。状態は規格ではなく実行時データとして版フォルダの外に置く。
- **判定と実行の分離**：時刻・間隔・期限の判定はスクリプト（トークン消費なし）、指揮はワークフロー、実行はエージェント。監査役（ドクター）が異常遷移だけを検知し、軽微なものは対処して報告、重大なものは報告して判断を仰ぐ。

## 3. プロジェクトと担当者

プロジェクトはユーザーのオーダーで生成され（概要＋スケジュール＋ワークフロー）、パッケージ化されればカタログに載り、選択して起動できる（プロジェクト＝アドオン）。

担当者は屋敷の使用人として管理される：

| クラス | 数 | 命名 |
|---|---|---|
| 執事 | 25（固定ペルソナ） | プロジェクト作成時に固定セットからランダムにアサイン。オーナーは命名不可。レアあり |
| メイド | 25（固定ペルソナ） | 同上 |
| じいや（執事長） | 1 | インストール時に命名可 |
| ばあや（メイド長） | 1 | インストール時に命名可 |
| 飛丸（忍者） | 1 | 名前不変（常に「飛丸」） |

- 家名：タマゴ内の財閥風ベース家名プールを材料に、インストール時にプロンプトで「良い感じの響き」に合成する（スクリプト固定ではない。運の要素あり）。
- ペルソナ解像度（選択可）：零＝無装飾／模糊＝語尾のみ／須臾＝口調に性格（仕事に影響しない）／虚空＝挙動にも性格が効く（タスクに影響が出ないギリギリまで）。阿摩羅は選択できない見せラベル。
- リセマラ：使用人全員の名前・ペルソナ・アバター属性を再生成できる（飛丸の名前だけは変わらない）。
- アバター：属性（服装・顔・体型・髪色・髪型・肌色・目色・3サイズ・身長・体重・年齢）はプロパティとして先に持ち、描画は後付けの GUI（Space 等）を入れた時点で行う「プロパティ先行・描画後行」。

## 4. 境界ルール（再掲）

- ユーザーはギャルではない。ギャル（お嬢／跡取り娘）は家の登場人物であり、デフォルトプロジェクト「AIに優しいギャル」のペルソナとして登場するが、オーナー本人ではない。自他境界をぼやかさない。
- 機構は無名。名を持つのはプロジェクト担当者だけ。
- 認証情報の値は規格・レジストリに書かない（参照だけ）。
- アクセス経路（どの環境・どの経路・どのサービスで動くか）はタスクごとに固定し、定義外の経路は使わない。
